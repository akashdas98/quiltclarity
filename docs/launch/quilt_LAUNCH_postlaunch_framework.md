# Quilt Utility Website — Post-Launch Decision Framework

**Authority:** `docs/v1.1/00_GOVERNING_AGENDA.md` governs product scope and reason-to-win; `04_CONTENT_SEO_ROUTES.md` governs page expansion; `05_ANALYTICS_VALIDATION.md` and `src/lib/analytics/analytics.ts` govern measurement. This framework proposes future choices; it does not reopen completed M9/M10 or Guides/help gates. The Feedback System is a planned V2 milestone, with `/corrections/` currently a noindex coming-soon page and no submission inbox.

## Evidence hierarchy

1. V1.1 governing agenda, golden rules, privacy, and accepted decisions as constraints
2. observed task completion and usability evidence, with its participant limits stated
3. Search Console query/page evidence
4. repeated feedback once a real collection channel exists
5. verified market/competitor change affecting the same-job boundary
6. aggregate signals from the implemented closed analytics taxonomy
7. intuition as a hypothesis to test

Do not treat the M9 guided-operator substitution or Guides owner MT-U01/MT-U02 PASS as independent target-quilter evidence. Until the V2 Feedback System exists, do not depend on a V1.1 feedback inbox.

## Query classification

### A — already satisfied

Optimize CTR/clarity only.

### B — existing page almost satisfies

Improve the existing page.

### C — distinct new recurring task

Evaluate for a new tool/page.

### D — adjacent but off-agenda

Default defer.

### E — irrelevant

Ignore.

## Expansion rules

Prefer:

- calculators adjacent to current math engine
- planner improvements
- cut-list compilation, exact-stock reconciliation, and clearer purchase/cutting execution
- reference data requested by actual queries
- explainability
- print/cutting improvements

Be skeptical of:

- pattern marketplace
- generic inspiration content
- social/community
- AI
- cloud accounts
- full quilt designer
- huge block library

## Kill/narrow review

Ask:

- Is organic impression volume growing?
- Are more query clusters appearing?
- Can pages reach top 20/top 10?
- Do users finish calculators?
- Do users complete the planner's distinctive stock, purchase, pattern, and cutting tasks?
- Is print rate meaningful?
- Does the allowed date-only returning-tool-user boolean indicate repeat use in aggregate?
- Is the workflow easier than alternatives?
- Does any optional monetization improve the product without interrupting the workflow?

Outcomes:

- expand
- continue
- narrow
- reposition
- kill

## Core rule

> **Do not reward the product for existing. Make it earn the next feature.**
