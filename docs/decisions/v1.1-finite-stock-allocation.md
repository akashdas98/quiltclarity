# V1.1 Finite-Stock Allocation

## Decision

Implement exact finite-stock packing as a bounded domain subsystem in `src/lib/domain/optimizer/finite-stock.ts`, separate from the existing variable-length fresh-bolt optimizer.

Each stock quantity expands into stable physical material-bin instances. Every placement carries fabric, source stock piece, stock instance, and material-bin identity. Candidate generation combines five piece orders, three bin-assignment policies, and two deterministic guillotine split directions; large inputs fall back to the six strip-friendly combinations. All candidates are independently validated before selection.

The M2 API is deliberately stock-only. Complete coverage returns zero for raw, buffered, and recommended additional purchase. Incomplete coverage returns those purchase fields as `null`, returns every unmet piece instance exactly once, and never creates a purchased-bin placement. M3 will compare finite-stock candidates with the fresh-bolt shortfall rather than changing this physical-bin engine.

Practical leftover rectangles use the packer's deterministic free-rectangle partition. Placement geometry and unused area are authoritative; returned rectangles are not represented as one contiguous remnant.

## Rationale

Finite remnants have bounded width and length, while purchased fabric has fixed usable width and a length that must be solved. Treating them as one shelf algorithm would blur physical identity, invite area subtraction, and make it difficult to prove that stock safety, WOF semantics, and purchase shortfall remain distinct.

Exposing alternative validated candidates gives M3 enough information to choose the assignment with the lowest raw purchase length. Returning exact unmet instances when purchase is disabled preserves truthful behavior now without prematurely implementing the M3 reconciliation objective.

## Consequences

- Exact stock geometry, edited preset dimensions, quantities, bin identity, orientation, and WOF constraints are enforced in one reusable engine.
- The candidate set is bounded and deterministic; it is a practical heuristic and does not claim global optimality.
- Existing stock dimensions are never inflated by safety allowance.
- M2 does not alter the existing fresh-bolt optimizer, project result, presentation layer, persistence schema, or planner UI.
- M3 must evaluate the exported finite-stock candidates before selecting a stock-plus-purchase plan; it must not greedily consume only the M2 selected allocation when a different assignment reduces purchase length.
