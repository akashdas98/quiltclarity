# V1.1 Guides and Contextual Help Repository Audit

**Date:** 2026-09-01  
**Baseline commit:** `1f2901a`  
**Handoff:** `docs/v1.1_GUIDES_HELP/`

## V1.1 REPOSITORY AUDIT

### Current architecture

- Astro static output with source-rendered page content.
- Framework-independent deterministic TypeScript domain, optimizer, persistence,
  analytics, and presentation modules.
- Vanilla planner and calculator controllers; no React dependency.
- Versioned local project persistence and separate allow-listed theme storage.

### Current planner model, optimizer, and persistence

- Schema version 2 owns top-level fabrics and cut requirements.
- Finite stock and variable-length purchased-bolt planning remain separate
  bounded subsystems composed by `reconcileProject`.
- Pattern comparison remains a stock-free fresh-fabric scenario.
- The planner persists valid edits locally and restores/migrates compatible
  projects without a backend.

### Current calculators and routes

- All eleven required calculators are implemented as static interactive routes.
- The current canonical planner route remains `/fabric-cutting-planner/`, which
  the migration contract explicitly permits in place of `/project-planner/`.
- The baseline sitemap contains 29 indexable routes.

### Current Guides

- Route structure: `/guides/` plus ten canonical hand-authored reference guides;
  two historical aliases are non-indexed.
- Product tutorials: absent.
- Quilting-reference content: present and reusable.
- Contextual field help: visible hints exist at selected fields, but there is no
  controlled help registry or reusable accessible help control.
- Contextual result help: absent as a distinct interaction layer.
- Accessibility behavior: guide pages are semantic and responsive, but no
  popover keyboard/close/focus contract exists because no popovers exist.
- Deep-link strategy: ordinary route links exist; the required stable planner
  tutorial anchors do not.
- Learning continuity: no Start Here hierarchy or Previous/Next sequence.

### Current manual-test convention and coverage

- `docs/manual-tests/` is the established convention.
- Existing artifacts cover differentiation hardening and the completed M9 guided
  owner/operator substitute.
- `npm run smoke:browser` covers Chrome and Edge, mobile-width behavior,
  accessibility contracts, persistence, print/PDF, analytics containment, and
  all current indexable routes.
- No Guides/help-specific MT-G/MT-H/MT-A/MT-S/MT-X suite exists.

### Golden and corrected domain status

- G01-G45: automated at their governed domain boundaries.
- Corrected HST four-at-a-time geometry: present.
- Shared joined-WOF seam-loss helper: present.
- The Guides bundle does not require domain or schema replacement.

### Reusable without change

- Domain calculations, reconciliation, optimization, persistence schema, and
  placement-derived presentation.
- Existing reference guides, guide layout foundation, static metadata/canonical
  machinery, calculator layouts, and browser/PDF harness.
- Existing visible correctness warnings and inline field hints.

### Needs extension

- Guides hub with Start Here, Common Workflows, and Quilting Reference.
- Quick Start and canonical full planner tutorial with stable anchors.
- Focused product/workflow guide routes and sequential navigation.
- Controlled contextual-help registry and reusable accessible interaction.
- Planner and calculator field/result help with exact deep links.
- Guides/help analytics using allow-listed guide/help identifiers only.
- Sitemap, static contracts, browser coverage, and the maintained manual suite.

### Stale or needs replacement

- The current Guides hub presents reference articles as the primary IA.
- `GuidePage` assumes every article ends in the same planner CTA and has no
  learning-path metadata or Previous/Next contract.
- The supplied entry point says to execute M0-M11, while its migration document
  defines only M0-M10. The repository's recorded post-M10 overhaul checkpoint is
  the coherent interpretation; completed M0-M10 are not reopened.

### Conflicts with the bundle

- The supplied package requires independently recruited novice sessions in its
  analytics/manual acceptance language. On 2026-09-01 the product owner directed
  that any such requirement be redesigned for the owner alone. The substitution
  is governed by `docs/decisions/v1.1-guides-owner-validation-substitution.md`.
- The handoff predates completed M9/M10 evidence. Those completed gates and their
  limitations remain authoritative project state.

### Open domain ambiguity

None. The overhaul explains existing product behavior and does not change a
Golden quilting rule.
