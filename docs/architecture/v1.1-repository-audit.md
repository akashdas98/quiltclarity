# V1.1 Repository Audit

**Audit date:** 2026-08-20  
**Scope:** Milestone M0 baseline; no product code changes

## Current architecture

- Astro 7 emits a static site. Core calculations are framework-independent TypeScript, presentation projections are separate TypeScript modules, and browser interaction uses vanilla TypeScript controllers.
- React is not installed. There is no application backend, database, authentication, server persistence, runtime calculation API, or AI path.
- Domain, presentation, persistence, analytics, and browser-controller boundaries are already explicit and are suitable for incremental V1.1 work.

## Current planner model

- `PlannerProject` contains an optional name, unit system, one project seam allowance, and nested `{ fabric, pieces }` entries.
- `FabricSpec` contains nominal/usable width, directionality, default rotation, safety, purchase increment, and optional notes.
- `PieceGroup` contains its own dimensions, quantity, cut/finished mode, optional rotation/orientation/WOF flags, label, and notes.
- The model has no project ID/schema metadata, top-level cut-requirement list, fabric assignment field, stock pieces, pattern-stated amount, or pattern-assumed WOF.

## Current optimizer

- `optimizeFabric` is a deterministic fresh-bolt-only row packer with six stable ordering strategies, remainder filling, placement validation, configurable weighted scoring, a 400-placement strategy fallback, and a 20,000-placement hard cap.
- A placement identifies a piece group and instance plus `x`, `y`, dimensions, and rotation. It has no material-bin or stock-instance identity.
- The optimizer solves one fixed usable width with variable used length. It does not allocate finite rectangles or compare stock-versus-purchase assignments.
- Project planning optimizes fabrics independently and also computes a diagnostic joint-versus-separate raw-length comparison.

## Current persistence schema

- Storage key: `quilter:planner-state`.
- Current envelope version: 1, containing the current `PlannerProject` shape.
- Version 0 migrates to version 1 without a project-model transformation because both envelopes use the same project type.
- Corrupt and unknown-version state is currently removed. V1.1 requires a new schema and stronger safe-field recovery/user-visible migration reporting.

## Current calculators and routes

- Implemented calculators: Fabric Yardage, Backing, Binding, HST, Block Count, Borders, and Sashing.
- Missing V1.1 calculators: Batting, QST, Flying Geese, and Pieces from Fabric / Stock Fit.
- The build emits 19 pages: 18 indexable routes plus the noindex 404. The planner is `/fabric-cutting-planner`; V1.1 specifies `/project-planner` but permits retaining the old URL when that avoids migration risk.
- V1.1 route/content gaps include the four calculator routes, a Guides index, the revised methodology/How It Works information architecture, and the additional specified guides.

## Golden tests present

- G18-G27: present and passing.

## Reusable without change

- Exact millimetre conversions, imperial formatting, finished-to-cut arithmetic, validation primitives, safety calculation, and strict upward purchase rounding.
- Existing seven calculator domain contracts, including corrected HST geometry and joined-WOF capacity.
- Fresh-bolt optimizer strategies, performance guardrails, deterministic placement validation, and project-per-fabric isolation as components beneath the new reconciliation layer.
- SVG/text/cutting-instruction projection from authoritative placements, with accessibility and print infrastructure.
- Static Astro shell, theme handling, privacy-safe analytics adapter pattern, canonical/sitemap/robots foundations, and much of the visual/accessibility styling.

## Needs extension

- New versioned project schema and migration from the current nested fabric/piece model.
- Finite-stock bin geometry, bin-aware placements, deterministic candidate assignment, purchase-shortfall reconciliation, leftovers, and independent fresh-pattern comparison.
- Lexicographic stock-aware selection where raw additional purchase outranks presentation/waste preferences.
- Rapid project-level cut-list table, keyboard flow, deterministic spreadsheet paste preview/confirmation, and responsive card equivalent.
- Stock and pattern settings, consolidated results, new calculator domain/UI, V1.1 routes/content, and expanded closed analytics taxonomy.

## Stale or needs replacement

- Planner fabric cards with nested piece subforms are unsuitable as the primary 20-40-row external cut-list compiler.
- Homepage/planner positioning still describes a generic cutting planner rather than the V1.1 compound reconciliation job.
- The current analytics taxonomy lacks stock, paste, pattern, shortfall, allocation, failure, and shopping-list events required by V1.1.
- Current persistence silently removes corrupt/incompatible state instead of exposing the V1.1 recovery outcome.
- The legacy differentiation fixture labels G31-G35 conflict with the authoritative V1.1 numbering.

## Conflicts with new Golden Rules

1. `orientationConstraint` is persisted and displayed but is not consulted during normalization, validation, packing, or placement validation. Therefore a declared crosswise/lengthwise constraint does not currently affect geometry.
2. `isWofStrip` currently disables rotation but does not itself resolve the required crosswise extent to the fabric's usable WOF. It behaves correctly only when the caller also enters the full usable width.
3. Fresh-bolt candidates use a weighted scalar score before deterministic tie-breaks. V1.1 requires lexicographic stock-aware selection for validity and raw additional purchase; the existing scorer can remain inside fresh-bolt planning but cannot govern reconciliation.
4. Persistence removal of corrupt/incompatible state conflicts with V1.1's requirement to preserve safely recoverable fields and report migration issues rather than silently discard them.

## Open domain ambiguity

None found in the V1.1 package. The orientation and WOF findings are implementation defects against explicit rules, not unanswered quilting questions.

## Baseline verification

- `npm run typecheck`: pass, zero diagnostics.
- `npm run lint`: pass.
- `npm test`: pass, 134 tests across 13 files.
- `npm run build`: pass, 19 pages.
- `npm run verify`: stops at `npm run format` because the supplied `docs/v1.1/*.md` files and one pre-existing `docs/v2` file are not Prettier-formatted. No supplied specification files were rewritten during M0.

## M1 entry conditions

Before schema implementation, rename the legacy differentiation G31-G35 identifiers so V1.1 fixture numbers are unambiguous, and lock orientation/WOF semantics with regression tests. Then introduce the new schema as an additive migration that preserves fresh-bolt-only behavior.
